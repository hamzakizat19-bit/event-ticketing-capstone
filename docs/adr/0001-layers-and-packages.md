# ADR-0001: Қабаттар және пакет ережелері

**Мәртебесі:** қабылданды · **Кезең:** M1 (1–2 апта)

## Контекст
Жүйенің бизнес-логикасы (брондау, баға, орындар) консольге де, сақтау түріне де тәуелді болмауы керек. Себебі соңғы нұсқада екінші Repository қосылады, ал UI кейін ауыстырылуы мүмкін.

## Нұсқалар
- **A.** Бір пакет, барлық класс бірге: тез басталады, бірақ тәуелділіктерді бақылау мүмкін емес.
- **B.** Төрт қабат `domain`, `service`, `infra`, `ui` және ArchUnit ережелері.

## Шешім
B нұсқасы таңдалды.
- `domain` ешкімге тәуелді емес. Мұнда модель, үлгілер және Repository интерфейстері тұрады.
- `service` тек `domain`-ге тәуелді.
- `infra` (файлдар, форматтар, арналар) `domain` пен `service` интерфейстерін іске асырады.
- `ui` тек `service` пен `domain`-ді пайдаланады.
- Нақты кластарды тек `App` (composition root) жасайды.

## Салдары
- `ArchitectureTest` ережелердің бұзылуын CI-де бірден ұстайды.
- Repository интерфейсі `domain`-де тұрады (порт), ал іске асыруы `infra`-да.
- Әр жаңа тәуелділік үшін «ол қай қабатқа жатады?» деп ойлану керек. Бұл аздап уақыт алады.
